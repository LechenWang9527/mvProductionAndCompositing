## 路线选择

1. **推荐：Canvas 混合镜头。** 用当前会话内置 `image_gen` 做少量主体插画/真实空间资产；沿用 `PHOTO` 调色与 `LAYOUTS`，把文字、数字、工程线、标注和歌词触发动作留在 Canvas。杜甫、茅屋和战场主体可用图；战争 7:6、缺陷定位和灯格作为程序叠加/表达。投入低，能最大限度保留现有镜头与时间轴。
2. **重点镜头做分层视差。** 只给茅屋/广厦等确实需要空间的段落分别准备背景、主体、前景（需要时用透明主体），Canvas 用慢推/横移及不同层速率；主体的显现、开裂、灯亮等仍由代码控制。更丰富，但素材对齐和裁切成本较高，不宜全片每镜都拆层。
3. **纯程序图形与排版。** 用于精确计数、结构剖面、数据、灯格和文字构形；让图形按语义生长、变形或成为下一镜的共同形状。事实性强，最稳定；只在这些内容本身足以讲清时使用，别用它替代真正需要人物/空间质感的画面。

**建议组合：** 路线 1 作全片底座，路线 2 限于杜甫/家屋等情绪与空间镜头，路线 3 承担战争与工艺等精确信息。`image2.5` 不作为 API 名称；生成入口用本会话已提供的 `image_gen`，生成物复制为工程资产。

### 素材选择与风格锁定

- **主体插画：** 歌词主语是具体人物、手势或有机物，且程序形状不易画自然时用；同一主体跨乐句复用同一资产。
- **程序图形：** 数量、剖面、关系、工序、文字笔画要准确时用；让图形自身完成增减、定位或变形。
- **局部图片：** 只需一处材质/物证作依据时裁一个小窗或底纹，保留主构图和字幕版面。
- **完整场景：** 地点本身承载情绪或空间变化时用一张场景底图；前景、歌词、标注与动作叠在 Canvas 上，不按每个名词换全幅背景。

先用杜甫木刻像与现有古风版式做一个合成定调帧；确定纸色、线刻密度、人物轮廓、留白和图文比例后，把同一帧作为后续 `image_gen` 的参考，并固定一段共同风格描述，仅替换主体/动作/景别。文字、年份、工程标注留给 Canvas，避免不同生成图内的文字和字形破坏一致性。`ancient`、`marpol` 继续使用现有分段色板，跨段共享线刻和颗粒规则，不强迫颜色完全相同。每张新图都与定调帧并排检查轮廓、黑白阶调和留白；不合格就先改资产，不靠更强滤镜掩盖。

### 可先打样的连续样段

按现有分镜，建议先渲染约 7 秒 **00:29.99–00:36.90**：杜甫主体入场→箱子叠入→箱线/标记接到长安格。它能同时检验人物图是否贴合木刻、字与图谁主导、两个语义段是否连贯。若这段成立，再接 00:36.90–00:45.64 的茅屋→广厦→小家变化。样片须为连续视频，检查正常速度播放及首/中/尾帧；静态拼图不能证明动作或衔接成立。

**通过条件：** 生成图与纸色/墨色统一；人物入场和箱子动作对应语音；至少一个形状承担镜间接力；歌词全程可读；相同 `renderAt(t)` 重复取帧不变；无丢图、黑帧或突兀闪切。声音词头仍待音源回听校正。

## 一手资料核对

- 图像生成官方指南把画面描述拆成主体、场景、光线和视角，并建议后续生成沿用先前参考图以维持角色一致。这里仅抽取为素材 brief 字段，不指向任何外部模型或 API：[Google AI 图像生成指南](https://ai.google.dev/gemini-api/docs/image-generation)。
- Canvas `drawImage` 可指定源图矩形并映射到目标矩形，支持局部裁切和缩放；与当前 `PHOTO.plate()` 的 Canvas 合成做法一致：[MDN Canvas `drawImage()`](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/drawImage)。
- Remotion 的官方说明以帧号作为画面输入，并说明每帧内容改变就形成动画；其当前帧/时长约定与本项目 `renderAt(t)` 的确定性时间求值相近。这里只参考时间模型，不建议迁移框架：[Remotion core idea](https://www.remotion.dev/docs/idea)、[Remotion timing](https://www.remotion.dev/docs/timing)。

**待验证：** 风格索引脚本调用未能启动，故按技能说明直接读 catalog/Markdown；本报告未渲染样段、未试听音源。表中动作、配色与衔接是交给主负责人筛选的候选，不是已完成镜头结论。
