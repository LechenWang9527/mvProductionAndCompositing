# 古代MV过程动画制作方法

适用范围：当前古代段返工。主线仍是完成MV；先验证前奏与首句样段，再把同一方法用于其余问题镜头。字幕保持“当前句、下一句、下下句”，现代段视觉暂不扩展。

## 1. 调查结论转成制作原则

当前返工的关键缺口是：部分镜头把一整张插画当成全部内容，程序只改变取景位置、透明度或几条装饰线；另一些镜头用简略物件轮廓承担主要叙事。局部路径、光效和人物错时入场确实存在，但还不足以清楚演出歌词里的事件。

已经找到的可用证据：

- DeepSeek `docs/external_deepseek/code_ai_prototype/ai_tools.html` 和 `code_report.html`：事件表驱动输入、执行、反馈、结果收束。按源码确认；独立页面尚未完成浏览器视觉验收，不能称为已验证的优秀成片。
- DrawAI `lib/motion/shotcraft/upstream/template/src/aifl/live/ScenePapers.tsx`：卡片落下后对已落定卡片产生压动；`SceneWbr.tsx`：正文擦显、历史项堆入。用于继承动作顺序和相互影响。
- DrawAI `lib/motion/shotcraft/upstream/demos/camera/depth-layer-moves/MultiplaneReal.tsx`：不同深度层的位移系数与落定停留。`data/timeline-travel/TimelineTravel.tsx`：相机经过节点，节点触发内容卡。
- DrawAI `lib/motion/mgstyles/upstream/demos/06-collage/index.html`：实际Canvas源码中的 `piece/rimmed/cutQuad/tornStrip/shadow` 提供纸片、图像切层和材质处理；不能把整套骨骼、太空等无关剧情搬进本片。
- `ref_mv/src/engine/draw.js`、`art.js`：独立内容层、遮罩和局部显影；接口与主工程不同，需要适配。

工具状态（本轮更新）：现有主工程、Playwright、FFmpeg可用；独立 `film/motion-v2/` 的 Remotion 4.0.484 / React 19.2.7 已安装并锁定，已复制且校验真实 Shotcraft Polish/Look 组件，前奏已通过本机Chrome与Remotion真实抽帧。DrawAI插件工具当前未连接；本轮使用本地仓库源码与真实Remotion渲染，不宣称调用了插件工具。v2不回退到v1 Canvas画法。

## 2. 每句歌词先变成一个可见事件

为镜头先写五项，再制作：

1. **初始状态**：谁、什么物体、什么界面，原先处于什么状态。
2. **触发**：歌词中的哪个词或哪一刻引发变化。
3. **操作**：打开、输入、发送、收到、累积、点亮、展开、翻转、经过等能看见的动作。
4. **反馈**：操作后出现什么结果；物件关系、数据或空间发生了什么改变。
5. **接续**：保留哪个对象、形状或位置，把结果带到下一镜。

示例：“同学群里有人上市”可以是群聊等待→新消息到达→列表让位→消息内容展开→读到消息；“你点了个赞”接着改变同一消息的点赞状态，再进入扣下手机。不可在每句开头重建一个互不相干的手机轮廓。

需要情绪停留的短句可以没有新操作，但必须继承前句已经建立的事件或结果。不能为了凑动作让每个对象不停晃动。

## 3. 素材、图形、运动分别负责什么

| 对象 | 制作方式 | 质量要求 |
| --- | --- | --- |
| 杜甫、刘邦、人胸前的马牌工牌、手与钥匙锁、复杂建筑/室内 | 图像生成或已有合格素材；必要时制作不同状态/独立部件 | 保留形体、脸部、服饰、材质和明暗；不能用程序几条线代画，也不能把有用明暗用阈值删掉 |
| 群聊、账单、订单、历史档案、时间轴 | 以成熟界面/排版组件构造；移植已有事件与状态代码 | 完整层级、对齐、文字、卡片、控件及反馈；物理手机可用素材，屏幕内容由独立UI层绘制 |
| 点燃、展开、翻页、纸片堆叠、消息滚动、节点经过 | 明确事件表与状态机；遮罩、独立部件、层间作用、缓动和停留 | 必须改变内容状态；不能主要依赖整图缩放或无关装饰线 |
| 光、蒸汽、风、轻微景深 | 独立效果层；支持主动作 | 方向与物体相符，不遮字幕；这些是二次运动，不能单独冒充剧情过程 |
| 固定歌词 | 现有统一三行字幕系统 | 中间不再用大歌词替代画面；保持位置和阅读形式稳定 |

单张图没有可动部件时，只能承担背景、主体肖像或某个状态。若剧情需要手开锁、持杯或人物办事，就补有对应动作关系的素材或分状态图，不能靠扭曲整个人物伪造动作。

## 4. 一个镜头的分层结构

按实际需要拆成：背景/环境、人物或实物、可变化的纸张/屏幕/订单、信息与反馈、光风等效果、固定字幕。常规镜头用3–5个有职责的内容层即可。

可见动作至少包含一个主过程，以及与之相关的层间关系。例如卷轴展开时：右卷轴头移动，纸面被揭开，纸上的节点随后建立；人物素材落在展开的纸上，有接触影与落定。不能把整幅“灯+卷轴+人物”同速平移后称为分层。

移植模板时记录：源文件与函数、动作顺序、时间参数、缓动、阴影/遮罩、相互作用，以及本片改了哪些内容。原版依赖真实3D/WebGL的效果，若选择它就使用对应引擎；不能用平面渐变假称还原了该效果。

## 5. 前奏与首句的具体施工表

时码由现有歌曲与镜头区间约束，前奏0–15秒，首句从14.990秒开始。以下是主负责人当前方案，样段视觉验收前允许调整动作节奏，不改音轨或歌词数据。

| 时间 | 可见状态与动作 | 必要素材/层 | 留给下一阶段的结果 |
| --- | --- | --- | --- |
| 0–3.5s | 灯体在暗暖环境中可辨；灯芯点燃，火焰建立，照明范围扩大 | 独立灯体、火焰、照明遮罩、台面/纸面 | 灯保持燃烧；光照到纸卷 |
| 3.5–7.4s | 灯照出纸卷；卷头移动、纸面逐步展开，卷边和落影随展开变化 | 独立纸卷/纸面、卷边、接触影；灯继续存在 | 一张展开的经历载体 |
| 7.4–14.990s | 纸面建立时间轨迹；杜甫、刘邦人物/档案先后落位，节点建立并停留 | 两张按用户参考生成的人物、档案承托、节点与轨迹 | 两位“过来人”的经历关系已建立 |
| 14.990–16.620s | 唱“我是过来人”时，已建立的两份档案成为主体并联结 | 延用上镜对象，位置变化有承接 | 不另放一组大歌词压住画面 |
| 16.620–20.401s | “一千年前”触发时间推进；节点经过、内容展开并落定，连接过去与今天 | 时间轴世界层、事件卡、前后景 | 观众看见时间与共同经历的关系；不写未经核实的具体历史年份 |
| 20.401–21.6s | 保留结果，转向后续夜晚/经历档案，不同时让所有层离场 | 保持主体；一个承接对象引向下镜 | 首句与后续叙述连续 |

这段的验收对象是连续MP4：必须能指认点燃、展开、人物/档案进入、时间节点推进四个过程。只交几张静帧不足以证明通过。

## 7. 实施与验收顺序

1. 逐镜表：原词、真实时码、初始/操作/反馈/接续、素材列表、模板具体函数。主负责人确定内容。
2. 素材检查：人物参考一致；主体完整；透明边无色边；图像比例与字幕区正确。图片生成后检查，未合格就修素材。
3. 先做前奏到首句的连续样段，使用原音与统一字幕；同时查看首/中/尾与每次状态变化前后帧。
4. 验收主过程：不看字幕能否看懂画面发生了什么；去掉整图相机运动后，是否仍有内容状态变化；图片与动作是否互相作用；停留是否足够阅读。
5. 验收画质：无儿童线画主体、无临时几何替代复杂实物、无硬纸色接缝/裁片、无人物变形或字幕遮挡。节点卡/UI细节在原尺寸清楚。
6. 验收运行：按任意时刻跳转可重建同一状态；新模块不得靠上一帧累积；实际MP4检查音轨、时长、帧率及完整解码。
7. 样段达到上述标准后再用于其余镜头。报告分清“已查源码、已实现、已抽帧、已导出、已看连续效果”，不能用规格PASS代替视觉通过。
